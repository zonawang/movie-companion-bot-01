# 用電影夥伴學 ADK：先完成第一個小循環

主軸是「ADK 如何讓 AI 使用工具完成任務」。先用一個 agent 做出產品行為，接著才需要研究多 agent 或 graph workflow。

## Phase 1｜新的 LINE Bot 能呼叫 ADK

重點：LINE 是入口、Gemini 是模型、ADK 是執行 agent 與工具的框架。

實作：依 [LINE 設定](line-setup.md) 建立新帳號，問「最近有什麼電影可以查？」，觀察終端機的 `now_playing` 工具呼叫。

完成證據：LINE 回覆截圖、終端機工具名稱截圖。截圖請遮住 token 與個人識別資訊。

文章題目建議：**我用 Google ADK 做了一個 LINE 電影夥伴：先讓 AI 學會使用工具**。先寫想解決的日常問題，再放 LINE → ADK → 工具 → LINE 的圖，最後記下實際成功與遇到的錯誤。

紀錄（2026-10-25）：新 LINE 帳號已完成串接。LINE 官方 webhook 測試為 200 OK，Use webhook 已啟用；使用者確認手機收到電影回覆，服務記錄確認 ADK 呼叫 `now_playing` 且 LINE 回覆成功。目前是虛構電影示範模式；真實手機截圖待補。詳見 [驗證紀錄](verification.md)。

## Phase 2｜接上真實電影資料

重點：工具帶回可查證的資料，模型負責整理；資料來源有自己的範圍與限制。

實作：填 TMDB token、切成 `tmdb` 模式，查一部真實電影的簡介與評論連結，再試一個不存在的片名。

完成證據：成功查詢、有來源連結、查無資料時沒有補造內容。上映候選清單不等於每間影院的場次。

文章題目建議：**AI 說得像真的還不夠：我讓電影夥伴先查資料，再回答**。

## Phase 3｜把聊天變成票根

重點：理解與抽取可以交給模型；確認、權限與寫入由程式驗證。

實作：輸入片名、日期、同伴與一句心得；先取消一次，再重新建立並確認，最後用同伴查回票根。

完成證據：確認前沒新增、取消不新增、確認後能查回、原始心得保留。

文章題目建議：**不只是查電影：我把觀影心得存成自己的票根收藏**。

## Phase 4｜準備分享

重點：展示一個完整需求如何從自然語言走到工具，再變成可追溯的結果。

實作：準備 3 分鐘示範：查電影 → 記票根 → 確認 → 用同伴找回；再示範一次無資料或取消。

完成證據：流程圖、真實操作截圖、測試結果與尚未串接的項目。之後再決定是否值得加入 graph workflow、推薦 agent 或 MINI App 收藏牆。
